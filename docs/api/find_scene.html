create

POST /robots/v0/jobs/find-scenes

Operation ID: create-find-scenes-job.

Authentication: basic token (accessToken) or bearer token (authorizationToken).

Request body

application/json

Property Type Required Description
parameters object Yes
parameters.asset_id string Yes The Mux asset ID of the video asset to segment into scenes. Audio-only assets are not supported.
parameters.language_code string No Preferred transcript language code to analyze when a matching transcript track is available. Defaults to the first ready transcript track on the asset.
parameters.min_scene_duration_ms integer No Preferred minimum scene duration in milliseconds for scaffolded transcript chunking. Defaults to 15000.
parameters.min_scenes integer No Optional lower-bound hint for scene segmentation. When provided, the model should avoid collapsing clearly distinct beats below this count when the content supports more granular scene boundaries.
parameters.output_steering object No Curated output_steering controls for execution scope, segmentation strategy, title style, narration detail, audience, brand terms, and topic taxonomy. Scope is enforced; other controls guide model behavior but do not guarantee exact output.
parameters.output_steering.audience string No Intended audience used as best-effort model guidance. Does not change the output schema.
parameters.output_steering.brand_terms array of string and any No
parameters.output_steering.narration_detail enum: concise, balanced, detailed No Best-effort guidance for how much detail scene narratives should include.
parameters.output_steering.scope object and any No
parameters.output_steering.segmentation_strategy enum: editorial_beats, topic_changes, visual_transitions, action_progression, instructional_steps No Best-effort guidance for the kinds of boundaries the scene finder should prefer.
parameters.output_steering.title_style enum: descriptive, editorial, search_optimized, accessibility No Best-effort title style guidance for generated scene titles.
parameters.output_steering.topic_taxonomy object No Controlled vocabulary used to steer scene concepts without changing the response schema.
parameters.output_steering.topic_taxonomy.allow_other boolean Yes When false, the model should prefer values from the taxonomy. When true, non-taxonomy values may be used when no taxonomy value applies.
parameters.output_steering.topic_taxonomy.name string No Optional customer-facing name for the taxonomy.
parameters.output_steering.topic_taxonomy.values array of object Yes Controlled vocabulary values used as best-effort model guidance.
parameters.output_steering.topic_taxonomy.values[].aliases array of string No Accepted alternate names that should normalize to the canonical label.
parameters.output_steering.topic_taxonomy.values[].description string No Short explanation of when this value applies.
parameters.output_steering.topic_taxonomy.values[].label string Yes Canonical taxonomy value to prefer when supported by the source content.
passthrough string No Arbitrary string stored with the job and returned in responses. Useful for correlating jobs with your own systems.

Example request body:

      "narration_detail": "balanced",
      "scope": {
        "end_time": 180,
        "start_time": 30
      },
      "segmentation_strategy": "editorial_beats",
      "title_style": "descriptive"
    }
  }
}
